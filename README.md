# نظام تشغيل المقاولين — سقالة MVP

تطبيق ويب حقيقي وقابل للتشغيل: مصادقة متعددة المستأجرين، فريق ودعوات أعضاء،
عروض أسعار (Devis) وفواتير (Facture) بترقيم تسلسلي وشعار وترويسة تلقائيين
وتصدير PDF عربي/فرنسي سليم، ميزات اختيارية قابلة للتفعيل/التعطيل لكل شركة،
إدارة مشاريع، ميزانية ومصروفات (مخطَّط مقابل فعلي)، أوامر تغيير تُحدّث
الميزانية تلقائياً، سجل يومي للموقع، مهام، تصدير CSV، واستعادة كلمة مرور.

## المكدس التقني

- **الخادم**: Node.js + Express + TypeScript، Drizzle ORM فوق PostgreSQL،
  مصادقة JWT، تحقق من المدخلات عبر Zod، حد لمحاولات تسجيل الدخول.
- **النشر**: صورة Docker جاهزة للإنتاج (متعددة المراحل، مستخدم غير جذري،
  فحص صحة `HEALTHCHECK`) — راجع "النشر عبر Docker" أدناه.
- **ZATCA (فاتورة السعودية)**: طبقة تنفيذ حقيقية (توليد/توقيع/إرسال) —
  راجع "توافق ZATCA" أدناه.
- **الواجهة**: React + Vite + TypeScript + Tailwind CSS، React Router،
  واجهة عربية RTL كاملة.
- **قاعدة البيانات**: PostgreSQL، نموذج بيانات متعدد المستأجرين (كل
  استعلام مُقيَّد بـ `company_id`).
- **PDF**: Playwright (Chromium بلا واجهة) يطبع ترويسة HTML — يضمن تشكيلاً
  عربياً صحيحاً (اتصال الحروف واتجاه RTL) لا توفره مكتبات PDF التقليدية.
- **الاختبارات**: Vitest + Supertest (عزل المستأجرين، حسابات أوامر التغيير،
  دورة حياة عروض الأسعار، الترقيم التسلسلي، تفعيل/تعطيل الميزات، تجزئة
  كلمات المرور).

## البنية

```
client/   واجهة React (RTL)
```

## التشغيل محلياً

### 1) قاعدة البيانات

عبر Docker (موصى به):

```bash
docker compose up -d
```

أو عبر PostgreSQL مثبّت محلياً — أنشئ قاعدة بيانات فارغة وحدّث
`DATABASE_URL` في `.env` ليطابق بيانات الاتصال لديك.

### 2) متغيرات البيئة

```bash
cp .env.example server/.env
# ثم عدّل server/.env حسب الحاجة
```

### 3) التثبيت والتهيئة

```bash
npm install
npx playwright install chromium --with-deps   # لتوليد PDF (مرة واحدة فقط)
npm run db:migrate --workspace server
npm run db:seed --workspace server   # بيانات تجريبية + مستخدم تجريبي (تطوير محلي فقط)
```

بيانات الدخول التجريبية بعد التهيئة (**للتطوير المحلي فقط**):

- البريد الإلكتروني: `demo@contractor-os.test`
- كلمة المرور: `demo1234`

⚠️ **لا تُشغّلي `db:seed` أبداً على قاعدة بيانات إنتاجية أو تحتوي بيانات
عملاء حقيقيين** — يرفض السكربت العمل عمداً عند `NODE_ENV=production` (راجع
`server/src/db/seed.ts`) لهذا السبب بالضبط. شاشة تسجيل الدخول في الواجهة
لا تعبّئ هذه البيانات تلقائياً — الحقول فارغة دائماً في أي بيئة، ويجب
كتابة البريد الإلكتروني وكلمة المرور يدوياً.

### 4) التشغيل

في نافذتي طرفية منفصلتين:

```bash
npm run dev:server   # http://localhost:4000
npm run dev:client   # http://localhost:5173
```

### 5) الاختبارات الآلية

```bash
npm run test --workspace server
```

تُفرِغ (TRUNCATE) قاعدة البيانات المتصلة بها بين كل اختبار — لا تُشغّليها
على قاعدة بيانات إنتاجية أو تحتوي بيانات حقيقية. للاختبار الآمن، أنشئي
قاعدة بيانات مخصّصة للاختبارات ووجّهي `DATABASE_URL` إليها قبل التشغيل.

- [x] نسبة ضريبة افتراضية قابلة للتخصيص، وكل فاتورة تُجمِّد نسبتها عند الإصدار (لا تتغير لاحقاً بتغيير الإعداد)
- [x] تصدير PDF بترويسة احترافية، بثلاث لغات مستقلة لكل مستند (عربي/فرنسي/إنجليزي) — كل عميل يحصل على اللغة التي يريدها
- [x] ميزات اختيارية قابلة للتفعيل/التعطيل لكل شركة من الإعدادات (تبدأ بالفوترة)
- [x] حد لمحاولات تسجيل الدخول (10 محاولات / 15 دقيقة لكل IP)
- [x] مجموع الضريبة والإيراد من الفواتير المُسدَّدة فقط، معروض كبطاقة إحصاء أعلى صفحة الفواتير
- [x] طبقة أمان ضد الانهيار الكامل: خطأ غير متوقع في أي طلب (مثل معرّف تالف) يُعيد رسالة خطأ لذلك الطلب فقط، بدل إسقاط الخادم بالكامل لكل المستخدمين
- [x] اختبارات آلية للمنطق الحرِج (عزل المستأجرين، حسابات مالية، عروض الأسعار، الترقيم، تفعيل الميزات، تعدد اللغات، مقاومة الانهيار)

## توافق ZATCA (فاتورة السعودية)

طبقة تنفيذ فوترة إلكترونية حقيقية (`server/src/lib/zatca/`): توليد وتوقيع مستندات UBL حقيقية (XAdES، رمز QR بكل الحقول)، طلب CSR/CSID، وإرسال حقيقي إلى بوابة FATOORA (Clearance للفواتير القياسية، Reporting للمبسّطة) — لا محاكاة، لا نتيجة مُلفَّقة. مفاتيح ZATCA الخاصة تُخزَّن عبر `ZatcaSecretStore` (تخزين تطويري في الذاكرة، أو AWS Secrets Manager في الإنتاج). راجع `docs/zatca/ARCHITECTURE_BOUNDARY.md` للحد الفاصل المتعمَّد بين "التنفيذ الآمن" (هذه الطبقة) و"قرار الامتثال" (خارج نطاق هذا المستودع تماماً — لا "امتثال مكتمل" ولا "مؤهل لإنتاج ZATCA" يُستنتج هنا).

## النشر عبر Docker

يوجد `Dockerfile` جاهز للإنتاج (للخادم فقط — الواجهة بناء Vite ثابت يُنشَر بشكل منفصل):

```bash
docker build -t midad-server .
docker run --rm --env DATABASE_URL=... midad-server node dist/db/migrate.js   # مرة واحدة
docker run -d -p 4000:4000 --env DATABASE_URL=... --env JWT_SECRET=... midad-server
```

التفاصيل الكاملة (متغيرات البيئة، مزوّدو البريد/التخزين/ZATCA، `HEALTHCHECK`) في `docs/PRODUCTION_LAUNCH_CHECKLIST.md`.

## ما ينقص قبل الإطلاق الحقيقي

**مبني بالكامل، يحتاج فقط حسابات/مفاتيح حقيقية عند التفعيل (وليس بناءً جديداً):**
- **بريد إلكتروني حقيقي** — `server/src/lib/mailer.ts` يدعم Resend فعلياً (`MAIL_PROVIDER=resend` + `RESEND_API_KEY` + `MAIL_FROM_ADDRESS`)، بمهلة زمنية محدودة (10 ثوانٍ) لكل طلب. بلا تعيين صريح في الإنتاج، الخادم يرفض العمل بدل الطباعة الصامتة في السجل.
- **تخزين سحابي للصور** — `server/src/lib/storage/` يدعم أي مخزن متوافق مع S3 فعلياً (AWS S3، Cloudflare R2، MinIO) عبر `STORAGE_PROVIDER=s3`. نفس قاعدة الرفض الصريح في الإنتاج تنطبق.
- **توافق ZATCA** — طبقة التنفيذ (توليد/توقيع/إرسال حقيقي) مبنية بالكامل (راجع القسم أعلاه)؛ ما ينقص هو بيانات اعتماد ZATCA حقيقية (CSR/CSID مُصدَّقة من ZATCA الفعلية) وقرار امتثال بشري صريح — لا شيء من هذا يُستنتج آلياً من هذا المستودع.

**لا يزال يحتاج بناءً حقيقياً:**
- عقود بتوقيع إلكتروني (تحويل عرض سعر مقبول إلى عقد رسمي)
- صفحات شروط الاستخدام وسياسة الخصوصية (مسودة أولى، تحتاج مراجعة قانونية بشرية لاحقاً)

**يحتاج تدخلاً خارجياً منك (حسابات/مفاتيح لا أملكها):**
- **تحصيل مدفوعات حقيقي** عبر Stripe — يحتاج حساب Stripe ومفاتيح API.
- **رسائل SMS** لتنبيهات تجاوز الميزانية — يحتاج حساب Twilio.
- **استضافة إنتاجية** فعلية (Docker جاهز — راجع القسم أعلاه؛ يحتاج فقط حساب استضافة يشغّله فعلياً، مثل Railway/Render/AWS/أي مضيف يدعم Docker).
- **مراقبة أخطاء** (اختياري لكن موصى به، مثل Sentry) — يحتاج حساب ومفتاح DSN.

## ملاحظات أمنية قبل أي استخدام إنتاجي

- غيّر `JWT_SECRET` إلى قيمة عشوائية طويلة.
- عيّن `MAIL_PROVIDER=resend` و`STORAGE_PROVIDER=s3` (أو ما يعادلهما) — الخادم يرفض العمل في الإنتاج بلا تعيين صريح لكليهما، فلا حاجة لتذكّر ذلك يدوياً، لكن يجب توفير بيانات الاعتماد الحقيقية قبل التشغيل.
- إن كانت ZATCA مطلوبة، عيّن `ZATCA_SECRET_STORE_PROVIDER=aws-secrets-manager` مع بيانات اعتماد AWS حقيقية — لا تستخدمي مخزن الذاكرة التطويري في الإنتاج أبداً.
