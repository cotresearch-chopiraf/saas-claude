# نظام تشغيل المقاولين — سقالة MVP

تطبيق ويب حقيقي وقابل للتشغيل: مصادقة متعددة المستأجرين، فريق ودعوات أعضاء،
عروض أسعار (Devis) وفواتير (Facture) بترقيم تسلسلي وشعار وترويسة تلقائيين
وتصدير PDF عربي/فرنسي سليم، ميزات اختيارية قابلة للتفعيل/التعطيل لكل شركة،
إدارة مشاريع، ميزانية ومصروفات (مخطَّط مقابل فعلي)، أوامر تغيير تُحدّث
الميزانية تلقائياً، سجل يومي للموقع، مهام، تصدير CSV، واستعادة كلمة مرور.

## المكدس التقني

- **الخادم**: Node.js + Express + TypeScript، Drizzle ORM فوق PostgreSQL،
  مصادقة JWT، تحقق من المدخلات عبر Zod، حد لمحاولات تسجيل الدخول.
- **الواجهة**: React + Vite + TypeScript + Tailwind CSS، React Router،
  واجهة عربية RTL كاملة.
- **قاعدة البيانات**: PostgreSQL، نموذج بيانات متعدد المستأجرين (كل
  استعلام مُقيَّد بـ `company_id`).
- **PDF**: Playwright (Chromium بلا واجهة) يطبع ترويسة HTML — يضمن تشكيلاً
  عربياً صحيحاً (اتصال الحروف واتجاه RTL) لا توفره مكتبات PDF التقليدية.
- **الاختبارات**: Vitest + Supertest (عزل المستأجرين، حسابات أوامر التغيير،
  دورة حياة عروض الأسعار، الترقيم التسلسلي، تفعيل/تعطيل الميزات، تجزئة
  كلمات المرور).

## البنية

## التشغيل محلياً

### 1) قاعدة البيانات

عبر Docker (موصى به):

```bash
docker compose up -d
```

أو عبر PostgreSQL مثبّت محلياً — أنشئ قاعدة بيانات فارغة وحدّث
`DATABASE_URL` في `.env` ليطابق بيانات الاتصال لديك.

### 2) متغيرات البيئة

```bash
cp .env.example server/.env
# ثم عدّل server/.env حسب الحاجة
```

### 3) التثبيت والتهيئة

```bash
npm install
npx playwright install chromium --with-deps   # لتوليد PDF (مرة واحدة فقط)
npm run db:migrate --workspace server
npm run db:seed --workspace server   # بيانات تجريبية + مستخدم تجريبي
```

بيانات الدخول التجريبية بعد التهيئة:

- البريد الإلكتروني: `demo@contractor-os.test`
- كلمة المرور: `demo1234`

### 4) التشغيل

في نافذتي طرفية منفصلتين:

```bash
npm run dev:server   # http://localhost:4000
npm run dev:client   # http://localhost:5173
```

### 5) الاختبارات الآلية

```bash
npm run test --workspace server
```

تُفرِغ (TRUNCATE) قاعدة البيانات المتصلة بها بين كل اختبار — لا تُشغّليها
على قاعدة بيانات إنتاجية أو تحتوي بيانات حقيقية. للاختبار الآمن، أنشئي
قاعدة بيانات مخصّصة للاختبارات ووجّهي `DATABASE_URL` إليها قبل التشغيل.

## الميزات المُنفَّذة

- [x] مصادقة (تسجيل شركة جديدة + تسجيل دخول) بمعزل كامل بين المستأجرين
- [x] استعادة كلمة المرور (رابط بريدي، يُطبع حالياً في سجل الخادم — راجع "يحتاج تدخلاً خارجياً" أدناه)
- [x] دعوة أعضاء الفريق (owner/member) بروابط دعوة
- [x] إدارة مشاريع (إنشاء، عرض، تعديل، حذف)
- [x] بنود ميزانية لكل مشروع + مصروفات فعلية + مقارنة مخطَّط/فعلي تلقائية
- [x] قائمة مهام لكل مشروع بحالات (لم تبدأ / جارية / منتهية)
- [x] أوامر تغيير (Change Orders) تُحدّث ميزانية المشروع تلقائياً عند الاعتماد
- [x] سجل يومي للموقع (Daily Log)
- [x] تصدير بيانات الميزانية إلى CSV
- [x] عروض أسعار للعملاء: إنشاء → إرسال → رابط عام يقبله/يرفضه العميل بدون تسجيل دخول
- [x] فواتير (Facture): مستقلة أو محوَّلة من عرض سعر مقبول بضغطة واحدة، حالة مدفوعة يدوية
- [x] ترقيم تسلسلي آمن من التصادم لكل شركة (`DEV-2026-0001`، `INV-2026-0001`)
- [x] شعار الشركة (رفع صورة) + معلومات الشركة (عنوان، رقم ضريبي، هاتف) تُملأ تلقائياً في كل مستند
- [x] نسبة ضريبة افتراضية قابلة للتخصيص، وكل فاتورة تُجمِّد نسبتها عند الإصدار (لا تتغير لاحقاً بتغيير الإعداد)
- [x] تصدير PDF بترويسة احترافية، بثلاث لغات مستقلة لكل مستند (عربي/فرنسي/إنجليزي) — كل عميل يحصل على اللغة التي يريدها
- [x] ميزات اختيارية قابلة للتفعيل/التعطيل لكل شركة من الإعدادات (تبدأ بالفوترة)
- [x] حد لمحاولات تسجيل الدخول (10 محاولات / 15 دقيقة لكل IP)
- [x] مجموع الضريبة والإيراد من الفواتير المُسدَّدة فقط، معروض كبطاقة إحصاء أعلى صفحة الفواتير
- [x] طبقة أمان ضد الانهيار الكامل: خطأ غير متوقع في أي طلب (مثل معرّف تالف) يُعيد رسالة خطأ لذلك الطلب فقط، بدل إسقاط الخادم بالكامل لكل المستخدمين
- [x] اختبارات آلية للمنطق الحرِج (عزل المستأجرين، حسابات مالية، عروض الأسعار، الترقيم، تفعيل الميزات، تعدد اللغات، مقاومة الانهيار)

## ما ينقص قبل الإطلاق الحقيقي

**يمكن بناؤه داخلياً (لا يحتاج حسابات أو مفاتيح خارجية):**
- عقود بتوقيع إلكتروني (تحويل عرض سعر مقبول إلى عقد رسمي)
- صفحات شروط الاستخدام وسياسة الخصوصية (مسودة أولى، تحتاج مراجعة قانونية بشرية لاحقاً)
- توافق ZATCA الكامل (فاتورة السعودية) إن كانت السعودية سوقاً مستهدفاً — رمز QR + ربط API إلزامي، أكبر من "حقل ضريبة" بسيط

**يحتاج تدخلاً خارجياً منك (حسابات/مفاتيح لا أملكها):**
- **بريد إلكتروني حقيقي** لاستعادة كلمة المرور ودعوات الفريق وإرسال عروض الأسعار — يحتاج مفتاح Resend أو SendGrid. حالياً تُطبع الرسائل في سجل الخادم فقط.
- **تحصيل مدفوعات حقيقي** عبر Stripe — يحتاج حساب Stripe ومفاتيح API.
- **تخزين سحابي للصور** (شعارات الشركات حالياً على القرص المحلي فقط — تُفقَد عند أي إعادة نشر على استضافة بلا قرص دائم؛ ينطبق أيضاً على بوابة قبل/بعد ومرفقات السجل اليومي مستقبلاً) — يحتاج حساب S3 أو Cloudflare R2.
- **رسائل SMS** لتنبيهات تجاوز الميزانية — يحتاج حساب Twilio.
- **استضافة إنتاجية** فعلية (Railway/Render/Vercel) — يحتاج حساباً تربطينه بمستودع GitHub هذا.
- **مراقبة أخطاء** (اختياري لكن موصى به، مثل Sentry) — يحتاج حساب ومفتاح DSN.

## ملاحظات أمنية قبل أي استخدام إنتاجي

- غيّر `JWT_SECRET` إلى قيمة عشوائية طويلة.
- اربطي مزوّد بريد حقيقي بدل الطباعة في السجل (`server/src/lib/mailer.ts`).
