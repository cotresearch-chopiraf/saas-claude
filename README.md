# نظام تشغيل المقاولين — سقالة MVP

تطبيق ويب حقيقي وقابل للتشغيل: مصادقة متعددة المستأجرين، فريق ودعوات أعضاء،
عروض أسعار للعملاء بقبول عبر رابط عام، إدارة مشاريع، ميزانية ومصروفات
(مخطَّط مقابل فعلي)، أوامر تغيير تُحدّث الميزانية تلقائياً، سجل يومي للموقع،
مهام، تصدير CSV، واستعادة كلمة مرور.

## المكدس التقني

- **الخادم**: Node.js + Express + TypeScript، Drizzle ORM فوق PostgreSQL،
  مصادقة JWT، تحقق من المدخلات عبر Zod، حد لمحاولات تسجيل الدخول.
- **الواجهة**: React + Vite + TypeScript + Tailwind CSS، React Router،
  واجهة عربية RTL كاملة.
- **قاعدة البيانات**: PostgreSQL، نموذج بيانات متعدد المستأجرين (كل
  استعلام مُقيَّد بـ `company_id`).
- **الاختبارات**: Vitest + Supertest (عزل المستأجرين، حسابات أوامر التغيير،
  دورة حياة عروض الأسعار، تجزئة كلمات المرور).

## البنية

```
server/   Express API
client/   واجهة React (RTL)
```

## التشغيل محلياً

### 1) قاعدة البيانات

عبر Docker (موصى به):

```bash
docker compose up -d
```

أو عبر PostgreSQL مثبّت محلياً — أنشئ قاعدة بيانات فارغة وحدّث
`DATABASE_URL` في `.env` ليطابق بيانات الاتصال لديك.

### 2) متغيرات البيئة

```bash
cp .env.example server/.env
# ثم عدّل server/.env حسب الحاجة
```

### 3) التثبيت والتهيئة

```bash
npm install
npm run db:migrate --workspace server
npm run db:seed --workspace server   # بيانات تجريبية + مستخدم تجريبي
```

بيانات الدخول التجريبية بعد التهيئة:

- البريد الإلكتروني: `demo@contractor-os.test`
- كلمة المرور: `demo1234`

### 4) التشغيل

في نافذتي طرفية منفصلتين:

```bash
npm run dev:server   # http://localhost:4000
npm run dev:client   # http://localhost:5173
```

### 5) الاختبارات الآلية

```bash
npm run test --workspace server
```

تُفرِغ (TRUNCATE) قاعدة البيانات المتصلة بها بين كل اختبار — لا تُشغّليها
على قاعدة بيانات إنتاجية أو تحتوي بيانات حقيقية. للاختبار الآمن، أنشئي
قاعدة بيانات مخصّصة للاختبارات ووجّهي `DATABASE_URL` إليها قبل التشغيل.

## ما ينقص قبل الإطلاق الحقيقي

**يمكن بناؤه داخلياً (لا يحتاج حسابات أو مفاتيح خارجية):**
- عقود بتوقيع إلكتروني (تحويل عرض سعر مقبول إلى عقد رسمي)
- فوترة داخلية (بدون تحصيل فعلي — سجل فواتير + حالة مدفوعة/غير مدفوعة يدوياً)
- رفع ملفات محلي مؤقت على القرص (كخطوة انتقالية قبل تخزين سحابي حقيقي)
- صفحات شروط الاستخدام وسياسة الخصوصية (مسودة أولى، تحتاج مراجعة قانونية بشرية لاحقاً)

**يحتاج تدخلاً خارجياً منك (حسابات/مفاتيح لا أملكها):**
- **بريد إلكتروني حقيقي** لاستعادة كلمة المرور ودعوات الفريق وإرسال عروض الأسعار — يحتاج مفتاح Resend أو SendGrid. حالياً تُطبع الرسائل في سجل الخادم فقط.
- **تحصيل مدفوعات حقيقي** عبر Stripe — يحتاج حساب Stripe ومفاتيح API.
- **تخزين سحابي للصور** (بوابة قبل/بعد، مرفقات السجل اليومي) — يحتاج حساب S3 أو Cloudflare R2.
- **رسائل SMS** لتنبيهات تجاوز الميزانية — يحتاج حساب Twilio.
- **استضافة إنتاجية** فعلية (Railway/Render/Vercel) — يحتاج حساباً تربطينه بمستودع GitHub هذا.
- **مراقبة أخطاء** (اختياري لكن موصى به، مثل Sentry) — يحتاج حساب ومفتاح DSN.

## ملاحظات أمنية قبل أي استخدام إنتاجي

- غيّر `JWT_SECRET` إلى قيمة عشوائية طويلة.
- اربطي مزوّد بريد حقيقي بدل الطباعة في السجل (`server/src/lib/mailer.ts`).
